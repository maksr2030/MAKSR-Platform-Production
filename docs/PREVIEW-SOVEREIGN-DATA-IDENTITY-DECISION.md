# MAKSR Preview Sovereign Data and Identity Provider Decision

Status: APPROVED FOR PREVIEW PROVISIONING
Date: 2026-09-13
Scope: Preview environment only
Production impact: NONE

## Decision

The selected managed PostgreSQL provider for the MAKSR Preview environment is Oracle Cloud Infrastructure Database with PostgreSQL, with the target region set to Saudi Arabia West (Jeddah), region identifier `me-jeddah-1`.

The selected OpenID Connect provider for the MAKSR Preview environment is Oracle Cloud Infrastructure Identity and Access Management with a dedicated non-default Identity Domain homed in Saudi Arabia West (Jeddah). Identity Domain replication must remain disabled unless a later sovereign-resilience decision explicitly authorizes another region.

The Preview environment must remain physically and logically separate from Production. No Preview database, identity domain, secret, encryption context, network, audit stream, credential, user population, or callback address may be shared with Production.

## Database Provider Evaluation Criteria

The provider decision was made against these mandatory criteria:

1. Data location and jurisdiction
2. Encryption at rest and in transit
3. Managed backups
4. Point-in-Time Recovery
5. Network isolation
6. Key and secret management
7. Audit and database logging
8. Compatibility with Vercel

## Provider Decision Summary

### Oracle Cloud Infrastructure Database with PostgreSQL

Decision: SELECTED

Strengths:

- Oracle Cloud Infrastructure has cloud regions in Saudi Arabia West (Jeddah) and Saudi Arabia Central (Riyadh), allowing the primary Preview data plane to remain inside Saudi Arabia.
- Oracle Cloud Infrastructure Database with PostgreSQL encrypts data at rest and in transit.
- Database endpoints are private and are not directly exposed to the public internet.
- Managed backups are supported with daily, weekly, and monthly scheduling and configurable retention.
- Point-in-Time Recovery is supported with a configurable recovery window of up to 35 days.
- PostgreSQL service logs can be exported to Oracle Cloud Infrastructure Logging or Object Storage, including audit logs generated by the PostgreSQL Audit Extension.
- Database administrator credentials can be stored in Oracle Cloud Infrastructure Vault rather than in source code or local configuration.
- Standard PostgreSQL protocol compatibility allows the existing MAKSR runtime database layer to remain provider-neutral.

Constraint:

- Direct private database connectivity from the current Vercel Pro runtime is not treated as an approved sovereign network path. The database remains private. Preview connectivity must be implemented through a controlled Saudi-hosted runtime access path, or through an explicitly approved private networking capability. Public exposure of the PostgreSQL endpoint is prohibited.

### Amazon Relational Database Service for PostgreSQL

Decision: NOT SELECTED FOR CURRENT PREVIEW

Strengths:

- Strong customer-managed key support through Amazon Web Services Key Management Service.
- Mature automated backups and Point-in-Time Recovery.
- Strong audit integration through Amazon Web Services CloudTrail.
- Strong Vercel private-connectivity story for Enterprise plans through Vercel Secure Compute and Amazon Web Services Virtual Private Cloud peering.

Reason not selected:

- As of this decision date, the Amazon Web Services Saudi Arabia Region remains announced rather than generally available. The currently available nearby Middle East Regions do not meet the preferred in-country Preview data-location objective.

### Microsoft Azure Database for PostgreSQL Flexible Server

Decision: NOT SELECTED FOR CURRENT PREVIEW

Strengths:

- Strong encryption and private network controls.
- Managed backups and high-availability capabilities.
- Nearby Middle East regions are available.

Reason not selected:

- Current documented PostgreSQL service-region availability does not provide the same in-country Saudi location advantage as Oracle Cloud Infrastructure.

### Supabase Managed PostgreSQL

Decision: NOT SELECTED FOR CURRENT PREVIEW

Strengths:

- Strong developer experience and PostgreSQL compatibility.
- Good integration patterns with Vercel.

Reason not selected:

- Current documented exact-region choices do not include a Saudi Arabia or Middle East region suitable for the MAKSR sovereign data-location objective.

### Neon PostgreSQL

Decision: NOT SELECTED FOR CURRENT PREVIEW

Strengths:

- Excellent Vercel integration and serverless PostgreSQL workflow.
- Strong development branching experience.

Reason not selected:

- Data-location and sovereign-control requirements take priority over developer convenience for this stage.

## OpenID Connect Provider Decision

### Oracle Cloud Infrastructure Identity and Access Management Identity Domain

Decision: SELECTED

A dedicated non-default Identity Domain must be created for MAKSR Preview.

Required properties:

- Home region: Saudi Arabia West (Jeddah)
- Environment: Preview only
- Domain replication: Disabled by default
- OpenID Connect enabled
- OAuth 2.0 authorization enabled
- Authorization Code flow enabled
- Proof Key for Code Exchange required
- Exact redirect Uniform Resource Identifier allowlist
- Exact post-logout redirect Uniform Resource Identifier allowlist
- Multi-Factor Authentication required for administrative users
- Separate Preview user population
- No Production users automatically imported
- No shared client secret with Production

Reason selected:

- Oracle Cloud Infrastructure Identity Domains support OpenID Connect, OAuth 2.0, Single Sign-On, identity federation, user lifecycle administration, and System for Cross-domain Identity Management.
- Additional Identity Domains can be created with a specified home region and are not replicated to other regions unless replication is explicitly enabled.
- The MAKSR runtime already validates OpenID Connect identity in a provider-neutral way, so this selection does not create application-level vendor lock-in.

## Sovereign Network Rule

The PostgreSQL database must remain on a private subnet. Direct public database exposure is forbidden.

The approved Preview network target is:

Vercel front end -> protected MAKSR Preview runtime endpoint -> Saudi Arabia West private application network -> private Oracle Cloud Infrastructure Database with PostgreSQL

The database credential must never be delivered to a browser or front-end bundle.

A later network implementation decision must select one of the following controlled paths:

1. Saudi-hosted MAKSR runtime service inside Oracle Cloud Infrastructure, preferred for sovereign data-plane isolation.
2. An approved private network connection from Vercel if the account plan and supported private-network technology provide a non-public path.

A public PostgreSQL endpoint is not an allowed fallback.

## Promotion Gates

No merge to `main` is allowed until all of the following are evidenced:

1. Oracle Cloud Infrastructure Preview database provisioned in Saudi Arabia West.
2. Database remains private and has no public PostgreSQL endpoint.
3. Preview Oracle Cloud Infrastructure Vault secret created and referenced operationally.
4. Database migrations `001_sovereign_foundation.sql` and `002_runtime_production_layer.sql` applied successfully.
5. Point-in-Time Recovery enabled and recovery window verified.
6. Automated backup policy verified.
7. Database service logging and PostgreSQL audit logging enabled.
8. Dedicated Preview Identity Domain created in Saudi Arabia West.
9. OpenID Connect client registered with exact Preview callbacks.
10. Preview session secret generated independently of all other environments.
11. Controlled first-organization bootstrap completed.
12. Authenticated Preview login completed successfully.
13. Organization, membership, role, and permission reads verified against the real Preview database.
14. Cross-organization access attempt rejected.
15. Audit event chain verification passes after real Preview administration activity.
16. Runtime health endpoint reports the real database and identity provider as ready without exposing secrets.
17. MAKSR public homepage remains byte-for-byte or browser-equivalent to the verified production baseline where no public interface change is intended.

## Production Boundary

This decision does not provision or authorize a Production database or Production Identity Domain. Production will receive a separate architecture decision, separate resources, separate secrets, separate backup policy, separate recovery objectives, and separate promotion approval.
